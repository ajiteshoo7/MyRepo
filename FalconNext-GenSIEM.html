Druva to CrowdStrike Integration for SIEM Capabilities

This guide provides a detailed process for integrating the Druva Cloud Platform with CrowdStrike. By configuring a **webhook** in Druva to send security events to CrowdStrike, your security operations center (SOC) can gain centralized visibility into both endpoint threats and data protection activities.

Prerequisites:

  • You must have a **CrowdStrike Falcon Next-Gen SIEM** license or a similar data ingestion plan that supports receiving third-party logs.
  • Ensure you have administrative access to both the **Druva Cloud Platform** and the **CrowdStrike Falcon** console.
  • Your network must allow communication from the Druva cloud to the CrowdStrike API endpoint.

The Integration Process

Step 1: Set Up a Data Ingestion API in CrowdStrike

CrowdStrike's SIEM solution provides a dedicated API for ingesting logs from external sources. You will need to create and configure this endpoint.

  • Log in to the **CrowdStrike Falcon** console.
  • Navigate to **Integrations > Next-Gen SIEM**.
  • Find the option to create a **Data Connector** or **Ingestion API** and provide a descriptive name (e.g., "Druva-Events").
  • CrowdStrike will generate a unique **API Endpoint URL** and an **API Key**. Copy both of these values. The API Key is critical for authentication.

Step 2: Configure the Webhook in the Druva Console

Now you will configure Druva to send its security events to the CrowdStrike endpoint you just created.

  • Log in to your **Druva Cloud Platform** console.
  • Navigate to **Integration Center** from the main menu.
  • Click on **Add Webhook**.
  • Provide a descriptive **name** for the webhook (e.g., "CrowdStrike-Events").
  • Paste the full **API Endpoint URL** from CrowdStrike into the webhook URL field.
  • Find the field for the webhook API key or token and paste the **API Key** you copied from CrowdStrike.
  • Select the specific **event categories** you want to send. Recommended categories include **Security Events** and **Audit Events**.
  • Save the webhook configuration.

Step 3: Verify Data Ingestion and Correlation

The final step is to confirm that events are being successfully sent from Druva and are visible within CrowdStrike's SIEM.

  • In your CrowdStrike Falcon console, navigate to the **SIEM** or **Event Search** area.
  • Search for a security event from Druva. For example, you can perform a login/logout action in Druva to trigger a test event.
  • The logs should appear in the CrowdStrike console, where you can now use them to build custom dashboards, set up alerts, and create correlation rules.

Example of a correlated event: You can create a rule to alert your SOC team if a "ransomware detected" event from CrowdStrike coincides with a "large file deletion" or "restore initiated" event from Druva for the same user or device.

This streamlined process provides a powerful way to unify your data protection and endpoint security telemetry, enabling your team to respond to threats with more context and speed.
